## 1. 문제 배경

`models/model_metadata.json` 에 `ml_beats_baseline_on_test: false` 가 기록돼 있었다.
189,411행으로 학습한 LightGBM 이 **"다음 분기 = 지난 분기"** 라는 한 줄짜리 규칙에 졌다.

| | test MAE | SMAPE | R² |
|---|---|---|---|
| LightGBM (학습본) | 13,776,289 | 29.16% | 0.925 |
| `baseline_last_quarter` (직전 분기 복사) | **13,572,510** | **26.80%** | **0.930** |

세 지표 모두 열세. 원인 가설 세 가지를 세웠다.

### 가설 1 — 타깃(정답지)이 오염됐다

`build.py` 가 타깃을 이렇게 만든다:

```python
grid[TARGET_COL] = _nan_divide(grid["next_당월_매출_금액"], grid["next_점포_수"])
```

그런데 원천 CSV 의 `점포_수`(`STOR_CO`)는 **전체 점포가 아니라 프랜차이즈를 제외한 일반 점포 수**다.
전체는 `유사_업종_점포_수` 이며, 다음 항등식이 **767,251행 전부**에서 성립한다:

```
점포_수 + 프랜차이즈_점포_수 == 유사_업종_점포_수
```

**측정된 왜곡** (실제 예: 이태원 관광특구 × 편의점, 2025Q2)

| | 값 |
|---|---|
| 전체 점포 | 24개 (일반 4 + 프랜차이즈 20) |
| 상권 총매출 | 5,374,108,949원 |
| 올바른 점포당 (÷24) | 223,921,206원 |
| **버그 (÷4)** | **1,343,527,237원 — 6.0배** |

업종별 평균 부풀림: 편의점 **3.34배**(최대 23배) · 치킨전문점 2.39배 · 패스트푸드점 2.00배.
반면 **100개 업종 중 56개는 1.00배**(프랜차이즈 없음) — 한식음식점도 1.09배라 영향이 거의 없었다.
**시연에서 주로 한식을 봤기 때문에 이 버그를 오래 발견하지 못했다.**

**왜 "숫자가 3배 큰 것"보다 나쁜가**: 배수가 일정하면 모델이 학습할 수 있다. 그런데 같은 편의점
안에서도 상권마다 **1.00배 ~ 23배**로 흔들린다. 모델 입장에선 학습 가능한 패턴이 아니라 **잡음**이다.
게다가 작은 분모로 나누면서 분포 꼬리가 두꺼워졌다(상위1%÷중앙값 **24.0배 → 32.5배**). MAE 는
큰 오차에 끌려가므로 소수의 폭발한 행이 성적을 지배한다.

> 참고: 피처 `점포당_매출_t` 도 같은 분모를 쓴다. 즉 **베이스라인("직전 분기 복사")은 이 버그에
> 면역**이다 — 왜곡이 t 와 t+1 사이에서 상쇄되기 때문. 반면 다른 피처를 쓰는 ML 만 잡음을 떠안았다.
> **모델이 유독 진 이유가 이것으로 설명된다.**

### 가설 2 — 수요 측 피처가 없다

학습 피처 29개 중 수요 관련은 유동인구 파생 5개뿐. 상주인구·직장인구·소득이 없다.
`config/data_sources.yaml` 에 `verified: false` 로 적혀 있었으나, **그 플래그를 읽는 코드는 없다.**
진짜 원인은 수집 목록(`src/legacy_api_config.py` 의 `SERVICE_NAMES`)에 두 서비스가 **아예 없어서
API 호출 자체가 안 된 것**이었다. 전처리 매핑(`aliases.py:82~`)과 병합 로직(`build_features.py:63~`)은
처음부터 준비돼 있었다.

### 가설 3 — 외부 피처(치안·부동산) 값이 NaN

`sf_*`·`re_*` 6개는 ablation 에서 채택된 학습 피처인데 서빙 테이블에서 값이 전부 비어 있다.

## 2. 검증 방법

**타깃 정의가 바뀌면 MAE 절대값은 비교할 수 없다.** (분모가 달라지면 정답 자체가 달라진다)
그래서 **각 실험 내부의 "모델 − 베이스라인 격차"** 로만 비교했다. 베이스라인도 매번 같은
타깃으로 다시 채점된다.

또한 커밋된 학습본은 외부 데이터가 있던 상태에서 나온 성적이라, 외부 데이터가 없는 이 머신
결과와 직접 비교하면 안 된다. 그래서 **대조군(Run A)을 이 머신에서 따로 만들었다.**

각 실험은 `build_features.py` → `train_model.py` 전체 재실행이며, 모델 zoo 6종
(naive 2 + RandomForest + XGBoost + LightGBM + CatBoost)을 매번 같은 조건으로 겨루게 했다.

## 3. 수정 내용

### 3-1. 타깃·피처 분모 (`src/features/build.py`, `schema.py`)

```diff
- df["점포당_매출_t"]  = _nan_divide(df["당월_매출_금액"], df["점포_수"])
+ df["점포당_매출_t"]  = _nan_divide(df["당월_매출_금액"], df["유사_업종_점포_수"])

- df["프랜차이즈_비율"] = _nan_divide(df["프랜차이즈_점포_수"], df["점포_수"])
+ df["프랜차이즈_비율"] = _nan_divide(df["프랜차이즈_점포_수"], df["유사_업종_점포_수"])

- grid[TARGET_COL] = _nan_divide(grid["next_당월_매출_금액"], grid["next_점포_수"])
+ grid[TARGET_COL] = _nan_divide(grid["next_당월_매출_금액"], grid["next_유사_업종_점포_수"])
```

피처와 타깃이 **같은 분모**여야 척도가 맞으므로 세 곳을 함께 고쳤다.

### 3-2. 모델 선정 (`config/settings.yaml`)

```diff
- valid_quarters: 1
+ valid_quarters: 2
```

**실험 중 발견한 두 번째 문제다.** 선정 로직(`train.py:149`)은 valid MAE 최소 모델을 고르는데,
valid 가 **단 한 분기**라 표본이 작아 그 분기에 과적합된 모델이 뽑히고 있었다:

```
LightGBM     valid 1위 → test 3위   ← 선정되고 있었음
RandomForest valid 2위 → test 1위   ← 실제로 더 나음
```

valid 를 2분기로 넓히자 순위가 뒤집혀 RandomForest 가 선정됐다.
**valid 로 고르는 설계 자체는 옳다**(test 로 고르면 성적이 부풀려진다). 표본이 작았던 것이 문제다.

3분기까지 넓히면 선정은 여전히 옳지만 학습 데이터가 28% 깎여(147,216 → 107,275) 성적이
−2.66% → −1.04% 로 후퇴했다. **2분기가 균형점.**

## 4. 결과 비교

실제 배포되는 성적은 `chosen_config_test_metrics`(ablation 채택 피처셋으로 재적합한 값)다.
모델 zoo 비교표(`model_comparison`)와 다른 숫자이니 혼동에 주의.

| | 선정 모델 | 피처 | 배포본 test MAE | vs 베이스라인 | SMAPE | R² | 이김 |
|---|---|---|---|---|---|---|---|
| ① 배포 중인 커밋본 | lightgbm | 29 | 13,776,289 | +1.50% | 29.16% | 0.925 | ✗ |
| ② 분모만 수정 | lightgbm | 23 | 10,702,876 | +0.35% | 28.25% | 0.927 | ✗ |
| **③ 분모 + valid 2분기** | **random_forest** | **11** | **10,340,404** | **−3.04%** | **26.41%** | **0.940** | **✓** |
| ④ ③ + 인구 피처 | random_forest | 25 | 10,395,552 | −2.53% | 26.48% | 0.938 | ✓ |
| *(②③④ 공통 베이스라인)* | | | *10,665,086* | | *26.44%* | *0.934* | |

**핵심: 두 수정이 모두 필요했다.**

- 분모만 고치면 여전히 LightGBM 이 뽑혀 패배 (+0.35%)
- 선정만 고치면 오염된 타깃 위에서 −1.59% 에 그침
- **둘 다 고쳐야 −3.04%**

③ 이 SMAPE 까지 베이스라인을 앞선다(26.41% vs 26.44%). 세 지표 전부 우세.

### ③ vs ④ — 인구 피처는 판정 불가(사실상 동률)

| | test 1분기 | **walk-forward 4-fold 평균** |
|---|---|---|
| ③ 인구 없음 | 10,340,404 | 10,582,908 |
| ④ 인구 포함 | 10,395,552 | **10,579,813** |
| 차이 | ③ 우세 0.53% | **④ 우세 0.03% — 동률** |

fold 별로도 2승 2패로 엎치락뒤치락한다. **단일 분기 결과로 ③이 낫다고 단정할 수 없다.**

## 5. 기각된 가설

### 가설 2 (수요 피처) — 기각

ablation 에서 인구를 추가해도 valid MAE 가 **0.08%** 밖에 줄지 않았다.

```
A_key_past_sales          feat=11  10,907,743
B_plus_population         feat=19  10,899,481   ← 인구 추가: -8,262 (-0.08%)
C_plus_store_competition  feat=24  10,917,675
C2_plus_seasonality       feat=25  10,897,873
```

**왜 기여하지 않았나 — 상관계수로 확인** (Spearman)

| | → 상권 총매출 | → 점포당 매출(타깃) |
|---|---|---|
| 상주인구 | −0.081 | −0.143 |
| 직장인구 | 0.265 | 0.123 |
| 유동인구 | 0.071 | −0.061 |

1. **타깃이 "점포당"이라 수요가 희석된다.** 사람이 많은 곳은 점포도 많이 들어와 나눠 먹으므로
   점포당 매출은 평준화된다. 인구가 만든 수요는 이미 `점포_수`(분모)에 흡수돼 있다.
   총매출 기준으로 보면 직장인구 상관이 0.265 인데 점포당으로 나누면 0.123 으로 절반이 된다
2. **기존 피처와 겹친다.** 상주인구 ↔ 유동인구 상관 **0.689** — 69% 는 이미 설명되고 있다
3. **상대가 너무 세다.** `직전분기 점포당매출 ↔ 타깃` 상관이 **0.962**. 여기에 0.14 짜리를
   더해도 개선이 드러나지 않는다

### 타깃을 "상권 총매출"로 바꾸는 방안 — 실익 없음

인구 상관이 2배라 검토했으나 측정 결과 기각:

```
상권 총매출 : 나이브 SMAPE 25.7% · 분기간 변동 중앙 14.6%
점포당 매출 : 나이브 SMAPE 26.4% · 분기간 변동 중앙 15.7%
```

**총매출도 "직전 분기 복사"로 잘 맞는다.** 오히려 조금 더 잘 맞아 AI 여지가 더 좁다.
그리고 총매출을 결정하는 건 인구가 아니라 **점포 수(상관 0.492)** 로, 예측이라기보다 동어반복에 가깝다.

사용자 관점에서도 "이 동네 한식 시장 140억"은 창업 판단에 직접 쓰이지 않는다. 결국 점포 수로
나눠야 하는데, 그러면 총매출 오차 × 점포수 오차가 겹쳐 **더 부정확해진다.**

### 가설 3 (외부 피처) — 효과 미미

ablation 실측: 치안 −65,935(−0.5%) 개선, **부동산은 +8,246 악화**. 값을 채워도 성능은
거의 변하지 않는다(예측값 평균 변동 ≈1.9%). 고쳐야 할 이유는 성능이 아니라
"학습에 쓴 피처인데 서빙 값이 비어 있다"는 **정합성**이다. 우선순위 낮음.

## 7. 남은 결정과 과제

### 결정이 필요한 것

1. **③ vs ④ (인구 피처 ML 편입 여부)** — 성능 동률. 성능이 기준이 못 되므로 설계 판단이다
   - ③ 유리: 피처 11개로 단순, 과적합 위험 낮음, 인구 CSV 없이도 재현 가능
   - ④ 유리: 이미 학습돼 있음, 추가 코드 불필요
   - **어느 쪽이든 인구 데이터는 상권 유형 분류와 웹 ⑦ 에서 계속 쓰인다** (ML 편입 여부와 무관)
2. **서빙 테이블·웹 산출물 재생성 여부** — 현재 배포본은 여전히 수정 전 데이터다.
   반영하면 편의점류 매출 과대추정이 해소되고 리포트의 관련 면책 문구도 조정 대상이 된다

### 남은 과제

- **롤링 백테스트** (`OPEN-ITEMS §10 ②`) — 지금 결과는 test 1분기 기준이다. 21개 분기로
  분기별 성적 흐름을 봐야 확정된다. 모델 없이 베이스라인만 채점하는 것은 이 머신에서 가능
- **업종별 채점** — 분모 오류가 편의점류에 집중됐으므로, 업종별 MAE 가 수정 전/후 비교 자료가 된다
- **문제 정의 재검토 (중장기)** — 현재 타깃은 나이브 규칙이 96% 설명하는 문제다.
  창업자가 실제로 묻는 것은 *"여기 **새로** 가게를 열면 얼마 벌까"* 인데, 이는 시계열 외삽이
  아니라 **반사실(counterfactual) 추정**이다. 기존 점포 이력을 쓸 수 없으므로 입지·인구·경쟁
  피처가 비로소 주역이 된다. 대안 후보: 신규 진입 매출 / 성장·쇠퇴 방향 분류 / 폐업 위험 분류
