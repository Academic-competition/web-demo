# 매출 예측 모델 개선 실험 — 해설판

> ML 배경지식 없이 읽을 수 있게 풀어 쓴 해설이다. 정확한 수치·재현 방법·상세 근거는
> 원 보고서 **[MODEL-EXPERIMENT-REPORT.md](MODEL-EXPERIMENT-REPORT.md)** 를 볼 것.
> 이 문서의 수치는 모두 원 보고서(실험일 2026-08-02~03)에서 가져왔고,
> "설명용 예시"로 표시한 것만 이해를 돕기 위한 가상의 숫자다.

---

## 0. 요약

- 매출 예측 모델(LightGBM)의 오차가 단순 규칙("다음 분기 = 지난 분기")보다 1.5% 컸다.
- 원인을 조사해 두 가지를 확인했다.
  1. 타깃(정답) 계산에 쓰인 `점포_수` 컬럼이 실제로는 **프랜차이즈를 제외한 일반 점포 수**였다
  2. 모델 선정에 쓰는 **검증 구간이 1개 분기**라, 특정 분기에 과적합된 모델이 선정되고 있었다
- 두 가지를 함께 수정한 결과 **ML 이 처음으로 단순 규칙을 앞섰다**
  (test MAE −3.04%, MAE·SMAPE·R² 3개 지표 모두 우세. 선정 모델은 RandomForest 로 변경).
- 함께 검토한 상주·직장인구 피처는 **매출 예측 성능에는 기여하지 않는 것으로 측정**됐다.
  대신 상권 유형 분류가 3종 → 5종으로 확장되는 확정 성과가 있었다.
- 변경 사항은 모델 저장소 브랜치에 있으며 **아직 서비스에는 반영 전**이다.

**읽기 전에** — 아래 두 원인은 모두 사후에야 드러나는 종류의 문제다. `점포_수` 라는
컬럼명은 전체 점포 수로 읽히는 것이 자연스럽고(실제 의미는 원천 데이터 명세의 함정이다),
검증 1분기는 통상적인 초기 설정이다. 이번 실험의 의의는 **베이스라인 비교라는 검증
절차가 문제를 드러냈고, 가설을 측정으로 확인해 개선했다**는 데 있다.

## 1. 기초 용어 3개

### MAE = "평균적으로 몇 원 틀렸나"

가게 3곳의 다음 분기 매출을 예측했다고 하자 (설명용 예시):

| | 예측 | 실제 | 오차 |
|---|---|---|---|
| 가게 A | 1.0억 | 1.1억 | 1,000만원 |
| 가게 B | 2.0억 | 1.8억 | 2,000만원 |
| 가게 C | 3.0억 | 3.3억 | 3,000만원 |

많이 불렀든 적게 불렀든 오차의 크기만 세서(절대 오차) 평균 낸다:
(1,000만+2,000만+3,000만)÷3 = **2,000만원 = MAE**. 작을수록 좋다.

보고서의 "모델 MAE 13,776,289" = "가게당 분기 매출을 평균 약 1,378만원 틀린다"로 읽으면 된다.

### 나이브 베이스라인 (단순 규칙)

> "이 가게의 다음 분기 매출 = **지난 분기 값을 그대로 사용**"

코드 한 줄짜리 비교 기준이다. **학습 과정이 없다** — 어떤 데이터를 줘도 하는 일은
"직전 값 복사" 하나다. ML 모델의 성능은 이 기준선을 얼마나 앞서는지로 평가한다.

### 학습 / 검증 / 테스트

데이터를 시간순으로 세 구간으로 나눈다.

- **학습**: 모델이 패턴을 배우는 구간 (과거 대부분)
- **검증(valid)**: 후보 모델 여럿 중 **최종 모델을 고르는** 용도 — 모의고사에 해당
- **테스트(test)**: 선택된 모델의 최종 성적. 마지막에 한 번만 사용 — 수능에 해당

시간순으로 나누는 이유: 무작위로 섞으면 미래 정보가 학습에 새어 들어간다.

## 2. 문제 상황

| | 오차(MAE) | |
|---|---|---|
| LightGBM (189,411행으로 학습) | 1,378만원 | |
| 단순 규칙 (직전 분기 복사) | 1,357만원 | 단순 규칙이 1.5% 우세 |

동네 매출은 관성이 강하다 — 지난 분기에 잘 되던 가게는 이번 분기도 대체로 비슷하다.
그래서 "직전 값 복사"는 생각보다 강한 기준선이다. ML 의 역할은 이 관성 **너머**의 변화
(성장하는 상권, 꺾이는 상권)를 잡는 것인데, 기준선을 넘지 못하면 모델을 쓸 근거가 약해진다.

원인 가설 3개를 세우고 전부 실측으로 확인했다. 결과: 2개 확인, 1개 기각,
그리고 예상하지 못했던 원인 1개를 실험 중 추가로 발견했다.

## 3. 원인 ① — 타깃 계산의 분모

### 내용

"가게당 매출 = 상권 총매출 ÷ 점포 수"를 계산할 때 원천 데이터의 `점포_수`(STOR_CO)를
썼는데, 이 컬럼의 실제 의미는 **프랜차이즈를 제외한 일반 점포 수**다.
전체 점포 수는 별도 컬럼 `유사_업종_점포_수` 이고, 원천 데이터 전 행에서
`점포_수 + 프랜차이즈_점포_수 = 유사_업종_점포_수` 가 성립한다.

실측 예 — 이태원 관광특구 × 편의점 (2025Q2):

| | 값 |
|---|---|
| 실제 점포 | 24개 (일반 4 + 프랜차이즈 20) |
| 전체 점포로 나눈 가게당 매출 (÷24) | 2.2억 |
| 일반 점포로 나눈 값 (÷4) | 13.4억 — **6배 과대** |

업종별 평균 과대 배수: 편의점 3.34배(최대 23배) · 치킨 2.39배 · 패스트푸드 2.00배.
반면 **100개 업종 중 56개는 1.00배**(프랜차이즈가 없어 두 컬럼이 같음), 한식도 1.09배.

### 왜 오래 발견되지 않았나

- 프랜차이즈가 없는 업종에서는 값이 완전히 정상이다. 시연에서 주로 본 한식 계열이
  여기에 해당해 화면상 이상이 드러나지 않았다
- 컬럼명만 보면 `점포_수` 가 전체로 읽힌다 — 원천 명세를 항등식으로 대조해야만 보이는 함정이다

### 왜 성능에 영향이 컸나

배수가 **일정하지 않다**는 점이 핵심이다. 항상 3배로 일정하다면 모델이 그 편향까지
학습할 수 있다. 그런데 상권마다 프랜차이즈 비율이 달라 같은 편의점 안에서도 1~23배로
흔들린다. 이런 변동은 학습 가능한 패턴이 아니라 **잡음**이 된다.

한 가지 더 — **단순 규칙은 이 문제의 영향을 거의 받지 않았다.** 같은 상권은 분기가
바뀌어도 프랜차이즈 비율이 비슷해서 과대 배수도 유지된다. "직전 값 복사"는 과대 계산된
값을 그대로 내고, 정답도 같은 방식으로 과대 계산돼 있으니 **왜곡이 복사 과정에서
상쇄**된다. 반면 ML 은 여러 상권을 섞어 패턴을 찾기 때문에 상권마다 다른 배수를 잡음으로
떠안는다. 두 방식이 같은 데이터에서 서로 다른 크기의 불이익을 받고 있었던 것이고,
**모델이 유독 뒤처졌던 이유가 이것으로 설명된다.**

## 4. 비교 방법 — 수정 전후를 공정하게 재는 법

### 분모 수정은 모델이 아니라 "데이터 표"를 고치는 것

"가게당 매출"은 원본에 있는 값이 아니라 나눗셈으로 만들어 표에 적는 값이다.
분모를 고치면 **표 전체가 다시 계산**된다 — 정답 칸(다음 분기 값)도, 단순 규칙이
복사해 오는 칸(지난 분기 값)도 모두 새 숫자가 된다. 그 같은 표를 두 방식이 함께 쓴다:

| | 새 표를 받으면 |
|---|---|
| ML 모델 | 새 표로 **재학습** 후 평가 |
| 단순 규칙 | 학습 과정이 없으므로 새 표에서 직전 값을 복사해 **재채점**만 |

### 수정 전후의 MAE 절대값은 직접 비교할 수 없다

분모를 고치면 정답 숫자 자체가 바뀐다 (위 예: 13.4억 → 2.2억). 오차의 원 단위 크기는
정답의 크기에 비례해서, 정답이 13.4억일 때 10% 틀리면 1.3억 오차지만 정답이 2.2억이면
같은 실력으로도 2,200만 오차가 된다. **모델이 좋아지지 않아도 정답 분포가 안정되면
MAE 숫자는 저절로 작아진다.** 그래서 "1,378만 → 1,034만, 25% 개선" 같은 비교는
성립하지 않는다 (발표 자료에서도 주의 — §10).

### 그래서 격차로만 판정했다

시험이 쉬워지면 반 평균도 같이 오른다. "몇 점"은 시험이 다르면 비교할 수 없지만
"**반 평균 대비 몇 점**"은 어느 시험에서든 실력을 나타낸다. 여기서 반 평균 역할이
단순 규칙이다 — **매 실험마다 단순 규칙을 같은 새 정답으로 다시 채점하고,
"모델 − 단순 규칙 격차"로만 승패를 판정했다.** 같은 실험 안에서의 비교는 항상 공정하다.

## 5. 원인 ② — 모델 선정 방식 (실험 중 추가 발견)

후보 모델 6종(나이브 2종 + RandomForest·XGBoost·LightGBM·CatBoost)을 겨루게 하고
검증(valid) 성적으로 최종 모델을 고르는데, 검증 구간이 **1개 분기**였다.
표본이 한 분기뿐이면 그 분기의 특성에 우연히 잘 맞은 모델이 선택될 수 있다. 실측:

```
LightGBM     valid 1위 → test 3위   ← 선정되고 있었음
RandomForest valid 2위 → test 1위   ← 실제 test 성적은 더 좋음
```

검증을 **2개 분기**로 넓히자 순위가 바뀌어 RandomForest 가 선정됐다.

- **"test 성적으로 고르면 되지 않나?"** → 안 된다. test 는 "미래" 역할이므로 선택에
  쓰면 미래 정보를 미리 보는 셈이 되어 성적이 실제보다 좋게 나온다. **valid 로 고르는
  설계 자체는 옳았고, 표본 크기가 부족했던 것이다.**
- **"3개 분기면 더 좋지 않나?"** → 검증에 분기를 더 떼줄수록 학습 데이터가 줄어든다
  (28% 감소). 실측에서 앞서는 폭이 절반 이하로 줄어, **2분기가 균형점**이었다.

| 실험 | 수정 내용 | vs 단순 규칙 | 판정 |
|---|---|---|---|
| ① 현재 배포본 | — | +1.50% | 열세 |

## 7. 상주·직장인구 피처 — 성능 기여 없음, 분류에는 활용

수요 측 데이터(상주·직장인구)를 추가하면 개선될 것이라는 가설은 실측에서 확인되지 않았다.
서로 다른 4개 분기로 나눠 재평가(walk-forward)한 결과 차이 ±0.03%, 2승 2패 — 동률이다.

이유는 세 가지로 설명된다:

1. **타깃이 "가게당"이라 수요 효과가 희석된다.** 인구가 많은 곳엔 점포도 많이 들어와서
   가게당 몫은 평준화된다. 인구의 효과가 이미 분모(점포 수)에 흡수돼 있는 셈이다.
2. **기존 피처와 정보가 겹친다.** 상주인구 ↔ 유동인구 상관 0.689 — 모델이 이미 보고 있는
   정보와 상당 부분 중복된다.
3. **직전 분기 매출의 설명력이 매우 크다.** "지난 분기 가게당 매출" ↔ 정답의 상관이
   0.962 라서, 상관 0.1대의 새 피처가 더해져도 개선이 드러나기 어렵다.

**다만 수집 자체는 성과가 있었다** — 이 데이터로 상권 유형 분류가 정식 규칙으로
동작하게 되어 3종 → 5종이 됐다(직장형 423 · 주거형 163 상권이 새로 배정).
매출 예측과 무관하게 확정된 개선이고, 웹의 배후지 섹션도 같은 데이터를 쓴다.
ML 편입 여부(§9 결정 A)와 관계없이 이 용도는 유지된다.

## 8. 함께 검토 후 접은 것 — 타깃을 "상권 총매출"로 변경

인구와 총매출의 상관이 가게당 매출보다 커서 검토했으나 기각했다.

- 총매출 역시 "직전 분기 복사"가 잘 맞는다 (오히려 가게당보다 약간 더 잘 맞아
  ML 이 개입할 여지가 더 좁다)
- 총매출의 주된 결정 요인은 점포 수(상관 0.492)로, 예측이라기보다 규모 확인에 가깝다
- 사용자 관점에서 "이 상권 시장 규모 140억"은 창업 판단에 직접 쓰이지 않는다.
  결국 점포 수로 나눠야 하는데 그러면 두 오차가 곱해져 더 부정확해진다

| 장점 | 구조가 단순, 과적합 여지 축소, 인구 데이터 없이도 재현 가능 | 이미 학습돼 있어 추가 작업 없음 |

**B. 반영 시점** — 반영하면 화면의 매출 숫자가 바뀐다(프랜차이즈 비중 큰 업종은 하향).
시연 일정과의 타이밍 조율이 필요하다.

### 반영 순서 (결정 후)

1. 브랜치를 main 에 병합
2. 서빙 테이블 재생성(`build_serving_table.py`) → 웹용 정적 산출물 재생성
   (`export_web_static.py`) → 커밋 (자동 배포). ※ `.venv` 와 원본 데이터가 있는
   머신에서만 실행 가능
3. 웹 측 동시 작업: `correctStoreCounts()` **제거** — 웹이 점포 수를 역산 보정하고
   있어서, 원천이 수정된 데이터가 오면 이중 보정이 된다. 배포 순서를 맞출 것.
   매출 과대 가능성 면책 문구도 조정 대상
4. 문서 정리: 기존 문서의 "ML 이 단순 규칙에 열세" 서술에 "수정 전 기준" 단서

### 남은 검증 — 롤링 백테스트

현재의 −3.04% 는 **마지막 1개 분기(test) 기준**이다. 21개 분기를 순회하며
"각 분기 시점에서 다음 분기 예측 → 실제와 비교"를 반복해 분기별 성적 흐름으로
확정하는 것이 남았다 (③vs④ 판정에 쓴 walk-forward 4회가 그 축소판이다).
업종별 채점을 함께 하면 분모 수정의 전/후 비교 자료도 된다.

## 10. 발표·보고 시 참고 의견

작성 과정에서 나온 의견들이다. 채택 여부는 팀 판단에 맡긴다.

1. **개선 "과정"이 그 자체로 발표 소재가 된다.** 베이스라인 비교라는 검증 절차가
   성능 문제를 드러냈고 → 원인 가설을 세워 → 실측으로 확인하고 → 수정 효과를 다시
   측정했다. 심사 관점에서 "모델을 만들었다"보다 "모델을 **검증하고 개선하는 체계**가
   있다"가 더 드문 강점이다. 기각된 가설(인구 피처)을 숨기지 않고 "측정해 보니 기여가
   없어 제외했다"고 말하는 것도 같은 맥락에서 신뢰를 준다.

2. **수치 인용 방식에 주의.** "MAE 1,378만 → 1,034만 (25% 개선)" 식의 전/후 절대값
   비교는 부정확하다 — 타깃 정의가 바뀌어 두 숫자는 다른 시험의 점수다 (§4).
   올바른 표현은 **"단순 규칙 대비 +1.5% 열세 → −3.04% 우세로 역전"** 이다.

3. **−3.04% 는 아직 1개 분기 기준이라는 단서를 유지할 것.** 롤링 백테스트로 확정되기
   전까지는 "최근 분기 기준" 표현을 권장. 확정되면 분기별 흐름 그래프가 더 강한
   발표 자료가 된다.

4. **서비스 관점 지표는 금액 오차보다 "추천 순위 적중률"이 설득력 있다.** 이 서비스가
   사용자에게 주는 것은 원 단위 금액이 아니라 추천 순위·등급이다. "작년 이맘때 우리가
   상위로 추천한 상권들이 실제로 상위였는가"를 보여줄 수 있으면 금액 오차보다 직관적이다
   (OPEN-ITEMS §10 의 평가 계획에 포함돼 있다).

5. **결정 A 에 대한 의견: ③(인구 미포함)을 권장.** 성능이 같다면 피처가 적은 쪽이
   유지보수와 설명에 유리하고, "성능 기여가 측정되지 않아 제외했다"는 서술이 발표에서도
   깔끔하다. 인구 데이터는 상권 유형·배후지에서 계속 활용되므로 수집 성과는 그대로 남는다.

6. **중장기 방향 멘트로 쓸 만한 것 — 문제 재정의.** 현재 타깃은 "기존 점포들의 다음 분기"
   라서 직전 분기의 설명력이 96%에 달하는, 원래 관성이 지배하는 문제다. 창업자의 실제
   질문은 "여기 **새로** 열면 얼마 벌까"이고, 이는 과거 이력이 없는 추정이라 입지·인구·경쟁
   피처가 비로소 주역이 되는 다른 문제다. 원 보고서 §7이 후보(신규 진입 매출, 성장/쇠퇴
   분류, 폐업 위험)를 정리해 뒀다 — "향후 과제" 슬라이드에 어울린다.
