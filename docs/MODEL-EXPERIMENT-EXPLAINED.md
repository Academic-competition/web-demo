## 1. 기초 용어 3개만 알면 됩니다

### MAE = "평균적으로 몇 원 틀렸나"

가게 3곳의 다음 분기 매출을 예측했다고 하자 (설명용 예시):

| | 예측 | 실제 | 틀린 정도 |
|---|---|---|---|
| 가게 A | 1.0억 | 1.1억 | 1,000만원 |
| 가게 B | 2.0억 | 1.8억 | 2,000만원 |
| 가게 C | 3.0억 | 3.3억 | 3,000만원 |

많이 불렀든 적게 불렀든 "틀린 건 틀린 것"으로 세고(**절대**오차), 평균을 낸다:
(1,000만+2,000만+3,000만)÷3 = **2,000만원 = MAE**. 작을수록 좋다.

보고서의 "모델 MAE 13,776,289" = "**가게당 분기 매출을 평균 1,378만원쯤 틀린다**"로 읽으면 된다.

### 바보 규칙 (나이브 베이스라인)

> "이 가게의 다음 분기 매출? **지난 분기 숫자를 그대로 베껴 적는다.** 끝."

코드 한 줄이고 AI가 아니다. **학습이라는 과정 자체가 없다** — 언제 어떤 데이터를 줘도
하는 행동은 "베끼기" 하나다. AI는 최소한 얘를 이겨야 존재 이유가 생긴다.

### 학습 / 검증 / 테스트 = 공부 / 모의고사 / 수능

데이터를 시간순으로 세 토막 낸다:

- **학습**(과거 대부분): 모델이 공부하는 구간
- **검증(valid)** = 모의고사: 후보 모델 여럿 중 **대표를 뽑는** 용도
- **테스트(test)** = 수능: 뽑힌 대표의 최종 성적. 마지막에 딱 한 번

시간순으로 자르는 이유: 랜덤으로 섞으면 미래를 컨닝하게 된다.

## 2. 문제의 시작 — AI가 한 줄짜리 규칙에게 졌다

| | 오차(MAE) | 결과 |
|---|---|---|
| LightGBM (19만 행으로 학습한 AI) | 1,378만원 | **패배** |
| 바보 규칙 (지난 분기 복사) | 1,357만원 | 승리 |

이게 왜 심각하냐면 — 동네 매출은 원래 **관성이 강하다**. 지난 분기에 잘 되던 김밥집은
이번 분기도 대충 잘 된다. 그래서 "복사"가 생각보다 세다. AI의 존재 이유는 이 관성 **너머**의
변화(뜨는 동네, 꺾이는 동네)를 잡는 건데, 그걸 못 잡으면 "AI 쓸 이유가 없다"가 된다.

왜 지는지 가설 3개를 세우고 전부 실측했다. 결과: **2개 적중, 1개 기각 + 예상 못 한 범인 1명 추가.**

## 3. 범인 ① — 오염된 정답지 (분모 버그)

### 버그 자체는 단순하다

"가게당 매출 = 동네 총매출 ÷ 가게 수"를 계산하는데, '가게 수'에 **프랜차이즈가 빠져 있었다.**
(원본 데이터의 `점포_수` 컬럼이 사실은 "일반 점포 수"였다. 전체는 `유사_업종_점포_수`)

실측 예 — 이태원 관광특구 × 편의점 (2025Q2):

| | 값 |
|---|---|
| 실제 점포 | **24개** (일반 4 + 프랜차이즈 20) |
| 올바른 가게당 매출 (÷24) | 2.2억 |
| **버그 값 (÷4)** | **13.4억 — 6배 뻥튀기** |

업종별 평균 뻥튀기: 편의점 3.34배(최대 23배) · 치킨 2.39배 · 패스트푸드 2.00배.
반면 **100개 업종 중 56개는 1.00배**(프랜차이즈 없음), 한식도 1.09배.
→ **시연 때 주로 한식을 봐서 오래 발견되지 않았다.**

### 왜 "숫자가 3배 큰 것"보다 훨씬 나쁜가 — 고장난 저울

- 저울이 **항상 정확히 2kg 더** 나온다 → 괜찮다. "2kg 빼고 보면 되네" — 일정한 오차는
  AI가 알아서 배운다.
- 이 저울은 **잴 때마다 1~23kg을 제멋대로** 더 얹는다 (상권마다 프랜차이즈 비율이 달라서).
  → 이건 오차가 아니라 **잡음**이고, 잡음은 학습이 불가능하다.

### 왜 바보 규칙만 멀쩡했나 — 이게 반전 포인트

같은 동네는 분기가 바뀌어도 프랜차이즈 비율이 비슷하다 → **뻥튀기 배수도 그대로 유지**된다.
"지난 분기 복사"는 지난 분기의 *뻥튀기된* 값을 그대로 내니까, *뻥튀기된* 정답과 잘 맞는다.
**왜곡이 복사 과정에서 상쇄**되는 것이다.

반면 AI는 유동인구·성장률 같은 다른 단서로 **여러 동네를 섞어** 패턴을 찾는데, 동네마다
배수가 제멋대로라 그 잡음을 정면으로 뒤집어쓴다.

> **즉 시합 자체가 불공평했다.** 바보 규칙만 버그에 면역인 경기장에서 싸우고 있었다.
> "AI가 유독 진 이유"가 이것으로 설명된다.

## 4. 채점의 함정 — 고치기 전에 알아야 했던 것

### 분모 수정 = 모델이 아니라 "표"를 고치는 것

"가게당 매출"은 원본에 있는 값이 아니라 **총매출 ÷ 가게수**로 계산해 표에 적어 넣는 값이다.
분모 수정 = 이 나눗셈을 고쳐 **표 전체를 다시 인쇄**하는 것. 표가 다시 인쇄되면
정답 칸(다음 분기 값)도, 바보 규칙이 베끼는 칸(지난 분기 값)도 전부 새 숫자가 된다.

그 **같은 표 하나**를 두 선수가 같이 쓴다:

| | 새 표를 받으면 하는 일 |
|---|---|
| AI | 새 표로 **다시 공부**(재학습)하고 시험 응시 |
| 바보 규칙 | 공부 없음. 새 표의 "지난 분기" 칸을 **베껴서** 응시 (재학습이 아니라 **재채점**) |

### 왜 수정 전/후의 MAE 를 직접 비교하면 안 되나

정답 숫자 자체가 바뀌기 때문이다 (이태원 편의점 정답: 13.4억 → 2.2억).
오차(원)는 정답의 덩치에 끌려간다 — 정답이 13.4억일 때 10% 틀리면 1.3억 오차,
정답이 2.2억이면 같은 실력이어도 2,200만 오차. **모델이 하나도 안 똑똑해져도
정답지가 얌전해지면 MAE 는 저절로 떨어진다.** 어제 어려운 시험 60점 → 오늘 쉬운 시험
70점을 "실력 향상"이라 부를 수 없는 것과 같다.

### 그래서 어떻게 비교했나 — 바보 규칙을 "자"로 쓴다

시험이 쉬워지면 반 평균도 같이 오른다. 그래서 "몇 점"은 시험끼리 비교 못 해도
"**반 평균보다 얼마나 잘 봤나**"는 어느 시험에서든 실력이다. 여기서 반 평균 = 바보 규칙.

**매 실험마다 바보 규칙을 같은 새 정답지로 다시 채점하고, "AI − 바보 규칙 격차"로만
승패를 판정했다.** 같은 실험 안(세로) 비교는 항상 공정하고, 다른 실험끼리(가로) MAE
원값 비교만 금지다.

## 5. 범인 ② — 엉터리 선수 선발 (실험 중 발견된 추가 범인)

후보 모델 6종(나이브 2 + RandomForest·XGBoost·LightGBM·CatBoost) 중 대표를
**모의고사(검증) 성적**으로 뽑는데, 모의고사가 **딱 1회분**(1개 분기)이었다.
1회 시험으로 뽑으면 "그 회차에 우연히 잘 찍은 애"가 뽑힌다. 실측:

```
LightGBM     모의고사 1위 → 수능 3위   ← 얘가 대표로 뽑히고 있었음
RandomForest 모의고사 2위 → 수능 1위   ← 진짜 실력자
```

모의고사를 **2회분(2분기)** 으로 늘리자 순위가 뒤집혀 RandomForest 가 뽑혔다.

- **"수능(test) 성적으로 뽑으면 되잖아?"** → 안 된다. 수능 문제를 미리 보고 대표를 뽑는 것
  = 컨닝. 성적이 부풀려져 실전(진짜 미래) 성적을 보장 못 한다. **뽑는 방식은 옳았고
  모의고사 회차가 부족했던 것.**
- **"3회분이면 더 좋지 않나?"** → 모의고사에 분기를 떼줄수록 **공부할 데이터가 깎인다**
  (28% 감소). 실측으로 이긴 폭이 절반 이하로 줄었다. **2분기가 균형점.**

## 6. 결과 — 둘 다 고쳐야 이긴다

| 실험 | 무엇을 고쳤나 | vs 바보 규칙 | 판정 |
|---|---|---|---|
| ① 현재 배포본 | (버그 2개 다 있음) | **+1.50%** 더 틀림 | 패배 |
| ② 정답지만 수정 | 분모만 | +0.35% | 아직 패배 — 과적합된 LightGBM 이 또 뽑힘 |
| **③ 둘 다 수정** | 분모 + 검증 2분기 | **−3.04% 덜 틀림** | **승리** ✓ |
| ④ ③ + 인구 피처 | | −2.53% | 승리 (③과 사실상 동률) |

②가 흥미롭다 — 정답지를 고쳐도 선발이 엉터리면 계속 진다. **두 문제가 서로를 가리고
있었다.** ③은 MAE 뿐 아니라 SMAPE·R² 까지 **3개 지표 전부** 바보 규칙을 앞선다
(처음 있는 일이다). 선정 모델은 LightGBM → **RandomForest** 로 바뀌었다.

## 7. 기대가 빗나간 지원군 — 상주·직장인구 피처

"사는 사람·일하는 사람 데이터를 넣으면 좋아질 것"이 원래 가설이었는데, 실측 결과
**기여 없음**(여러 분기로 나눠 재시험한 walk-forward 에서 ±0.03% — 동전 던지기 수준,
2승 2패). 이유 3가지가 전부 직관적이다:

1. **타깃이 "가게당"이라 수요가 희석된다.** 손님 많은 동네엔 가게도 많이 들어온다.
   파이가 커지면 나눠 먹는 사람도 늘어서 **가게당 몫은 어디나 비슷**해진다.
   인구의 효과는 이미 분모(가게 수)에 흡수돼 있었다.
2. **이미 아는 얘기와 겹친다.** 상주인구 ↔ 유동인구 상관 0.689 — 모델이 이미 보고 있는
   유동인구와 **같은 말을 두 번 듣는 셈**이다.
3. **경쟁 상대가 너무 세다.** "지난 분기 가게당 매출" ↔ 정답의 상관이 **0.962**.
   정답을 96% 설명하는 단서가 이미 있는데 0.14짜리 단서를 더해봤자 티가 안 난다.

**단, 헛수고가 아니었다** — 인구 데이터 덕에 **상권 유형 분류가 3종 → 5종**으로 살아났다
(직장형 423 · 주거형 163 상권이 처음 배정됨). 매출 예측엔 못 써도 리포트 설명력에는
확실한 기여. 이건 성능과 무관하게 확정된 개선이고, 웹 배후지 섹션도 같은 데이터를 쓴다.

## 8. 검토했다 접은 것 — "타깃을 동네 총매출로 바꾸면?"

인구와 총매출의 상관이 2배라 검토했지만 기각:

- 총매출도 "지난 분기 복사"가 잘 맞는다 (오히려 더 잘 맞아서 AI가 낄 자리가 **더 좁다**)
- 총매출을 결정하는 건 인구가 아니라 **가게 수**(상관 0.492)였다 — "가게 많은 동네가
  시장이 크다"는 동어반복이라 예측이라 부르기 민망하다
- 사용자에게 "이 동네 한식 시장 140억"은 창업 판단에 못 쓴다. 결국 가게 수로 나눠야
  하는데 그러면 오차 두 개가 곱해져 더 나빠진다

## 9. 다음 스텝

**중요: 아직 아무것도 실서비스에 반영되지 않았다.** 수정 코드·새 모델은 모델 저장소
브랜치 `fix/target-denominator-and-model-selection` 에만 있고, 배포된 웹 데모는 여전히
수정 전 데이터다 (편의점류 매출 뻥튀기가 화면에 그대로). 실험실 검증은 끝났고
생산라인 투입 전 단계다.

### 결정이 필요한 것 2가지

**A. 인구 피처를 모델에 넣을까 (③ vs ④)** — 성능 동률이라 설계 판단이다.

| | ③ 인구 없이 (피처 11개) | ④ 인구 포함 (피처 25개) |
|---|---|---|
| 장점 | 단순, 과적합 위험 낮음, 인구 CSV 없어도 재현 가능 | 이미 학습돼 있음, 추가 작업 없음 |

(참고 의견: 성능이 같다면 부품 적은 ③ 쪽이 정비·설명에 유리하다는 의견이 있음.
결정은 팀 몫.) **어느 쪽이든 인구 데이터 자체는 계속 쓴다** — 상권 유형 분류와
웹 배후지는 ML 편입 여부와 무관.

**B. 배포 반영 타이밍** — 반영하면 화면 매출 숫자가 바뀐다(편의점류는 크게 내려감).
내용상 반영 안 할 이유는 없고(지금 숫자가 틀린 것), 시연 일정과의 타이밍만 정하면 된다.

### 반영 순서 (결정되면)

1. 브랜치 → main 병합
2. 서빙 테이블 재생성(`build_serving_table.py`) → 웹용 JSON 재생성(`export_web_static.py`)
   → 커밋 → 자동 배포. ⚠️ **`.venv`+원본이 있는 머신에서만 가능** (`C:\_develop\academy`)
3. 웹 쪽 동시 작업: `correctStoreCounts()` **제거 필수** — 웹이 점포 수를 임시 역산
   보정 중이라, 원천이 고쳐진 데이터가 오면 **이중 보정**이 된다. 배포 순서를 맞출 것.
   면책 문구(매출 과대추정 경고)도 조정 대상
4. 문서 정리: 곳곳의 "ML 이 1.5% 열세" 서술에 "수정 전 기준" 단서

### 남은 검증 — 롤링 백테스트

지금의 −3.04%는 **수능 한 번**(마지막 1개 분기) 결과다. 21개 분기를 돌며
"매 분기 시점에서 다음 분기 맞히기"를 반복해 분기별 성적 흐름으로 확정해야 한다
(③vs④ 판정에 쓴 walk-forward 4회가 이미 축소판). 업종별 채점을 곁들이면
분모 수리의 비포/애프터 자료도 된다. 평가 프레임: [OPEN-ITEMS.md](OPEN-ITEMS.md) §10.

## 10. 보고·발표용 요약 문장

- 문제: AI가 "지난 분기 복사" 규칙에 1.5% 지고 있었다
- 원인 ①: 정답지 오염 — 가게당 매출의 분모에서 프랜차이즈가 빠져 상권마다 1~23배 잡음.
  복사 규칙만 이 버그에 면역이라 시합이 불공평했다
- 원인 ②: 대표 모델을 뽑는 검증이 1개 분기뿐이라, 그 분기에 과적합된 모델이 뽑히고 있었다
- 조치: 분모 교체 + 검증 2분기 확대 → 선정 모델이 RandomForest 로 바뀌며
  **최초로 3지표 전부 승리 (MAE −3.04%)**
- 기각: 상주·직장인구는 매출 예측에 무기여(수요가 분모에 흡수) — 단 상권 유형 5종
  복원이라는 확정 성과
- 남은 것: 배포 반영 결정(인구 피처 포함 여부 · 타이밍), 21개 분기 롤링 백테스트
