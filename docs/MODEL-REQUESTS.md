## 왜 저희가 직접 못 하나

파이프라인 실행 환경이 저희 개발 PC에 없습니다 — `Commercial-AI-/.venv` 와 `data/` 가 없어서
`scripts/*.py` 를 돌릴 수 없습니다. 현재 웹은 **다른 머신에서 만들어 커밋된 `model-exports/`** 를
그대로 쓰고 있습니다. (안전점수·배후지 산출물은 원본 CSV만 필요해서 저희가 만들었습니다.)

## 요약 — 3건 (+선택 2건)

| # | 요청 | 재학습 | 기대 효과 | 근거 |
|---|---|---|---|---|
| 1 | 외부 데이터(치안) 값 채우기 | **불필요** | 학습된 피처가 실제로 동작 (ablation MAE −0.5%) | §1 |
| 2 | 상주·직장인구 수집 활성화 | 필요 | 수요 측 피처 공백 해소, 상권 유형 3종→5종 | §2 |
| 3 | 매출 타깃 분모 수정 | 필요 | **예측값 과대추정 해소** (정의 오류) | §3 |
| 4 | 라이브 API 3개 보강 | 불필요 | 라이브 경로가 정적과 동등해짐 | §4 |
| 5 | `meta.sources` 필터링 | 불필요 | 안 쓴 출처를 나열하지 않게 | §5 |

**권장 순서**: 3 → 2 (한 번의 재학습으로 묶기) → 1 → 4 → 5
사유: 3번은 성능과 무관하게 **지표 정의 오류**라 먼저 고쳐야 하고, 2번과 함께 재학습하면
재학습을 두 번 하지 않습니다. 1번은 재학습이 필요 없어 언제든 가능합니다.

## 1. 외부 데이터(치안) 값 채우기 — 재학습 불필요

### 현상

`models/model_metadata.json` 의 학습 피처에 아래 6개가 **포함**되어 있습니다.

```
sf_crime_rate_per_100k, sf_arrest_rate, sf_cctv_per_km2,
re_rent_per_m2, re_vacancy_rate, re_rent_index
```

`chosen_step: "E_plus_safety"`, `external_features_included: true` — ablation 에서 채택된
피처입니다. 그런데 **현재 서빙 테이블에서 이 6개 값이 전부 NaN** 입니다.

원인은 `web-demo/tools/prepare_feature_table.py` 입니다. 외부 데이터 없이 파이프라인을 돌릴 때
학습본이 요구하는 컬럼만 NaN 으로 만들어 줍니다(0·평균 대치는 하지 않음). 그래서:

- 매출 예측: 모델이 이 피처를 '모름' 으로 처리 (예측값 평균 차이 ≈1.9%, 위 스크립트 주석의 측정치)
- `overall_score`: `safety_score` 5% 성분이 NaN → `src/serving/diagnosis.py:47` 의
  `overall_score()` 가 결측 성분을 제외하고 가중치를 재정규화 → **실질적으로 치안 미반영**

### 먼저 확인 부탁 — 그 파일이 이미 있으실 것 같습니다

학습 시점(`trained_at: 2026-07-24`)에는 **외부 데이터가 있었던 것으로 보입니다.**

- `ablation_valid` 에 `D_plus_real_estate`·`E_plus_safety` 단계가 실제로 측정돼 있습니다
- `exports/meta/external_columns.json` 의 `data_as_of` — 범죄 2024, CCTV 2025, 임대 2026Q1
- `scripts/build_features.py:85,93` 은 파일이 없으면 해당 단계를 **자동 생략**합니다
  (`"[안내] 안전 데이터(crime_gu/cctv_gu.csv) 없음 → sf_* 미생성 (Ablation E 자동 생략)"`)

즉 그때 `data/raw/external/` 에 `crime_gu.csv`·`cctv_gu.csv`·`rone_rent.csv` 가 있었을 것입니다.
**그 파일들이 아직 남아 있으면 이 요청은 "파이프라인 재실행" 만으로 끝납니다.** 저희 환경에는
그 폴더가 없어서 값이 비어 있는 상태로 재생성됐습니다.

파일이 남아 있다면 저희에게 공유해 주셔도 좋습니다 (작은 CSV 3개). 그러면 이후 산출물
재생성은 저희 쪽에서도 가능해집니다.

### 파일이 없어졌다면 — 저희 원본으로 만들 수 있습니다

`scripts/build_features.py:82-101` 이 `data/raw/external/` 에서 아래 이름으로 찾습니다.
`src/features/external.py:52-53` 이 요구하는 컬럼:

```
crime_gu.csv : 자치구, 연도, 범죄_발생_건수, 범죄_검거_건수, 인구
cctv_gu.csv  : 자치구, 연도, cctv_대수, 자치구_면적_km2
rone_rent.csv: 조사상권명, 자치구, 기준_년_코드, 기준_분기_코드, 엑스좌표_값, 와이좌표_값,
               임대료_원_m2, 공실률, 임대가격지수
```

- `crime_gu.csv` 재료: 저희가 받은 **5대 범죄 발생·검거(자치구별, 2024)** + **주민등록인구**
- `cctv_gu.csv` 재료: **범죄예방 CCTV 설치현황(2025, xlsx)** + 자치구 면적
  (면적은 `web-demo/tools/build_safety_scores.py` 의 `GU_AREA_KM2` 상수에 25개 구 값이 있습니다)
- `rone_rent.csv` (임대시세)는 **저희에게 없습니다** (한국부동산원 R-ONE 별도) → 없으면
  `re_*` 는 계속 NaN 이고 Ablation D 가 생략됩니다. 아래 '기대 효과' 를 보면 우선순위는 낮습니다

실행: `build_features.py` → `build_serving_table.py` → `web-demo/tools/export_web_static.py`
(외부 데이터가 있으면 `prepare_feature_table.py` 는 건너뛰면 됩니다)

## 3. 매출 타깃 분모 수정 — 재학습 필요 (우선순위 1위)

### 현상

프랜차이즈 비중이 큰 업종에서 점포당 예측 매출이 과대합니다.

### 원인 — 원천 컬럼의 의미

`점포_수`(`STOR_CO`)는 전체 점포 수가 아니라 **일반(비프랜차이즈) 점포 수**입니다.
전체는 `유사_업종_점포_수`(`SIMILR_INDUTY_STOR_CO`) 입니다. 원천 데이터에서 아래 항등식이
성립합니다.

```
점포_수 + 프랜차이즈_점포_수 == 유사_업종_점포_수
```

**저희가 받은 점포-상권 CSV 380,747행(2025Q1~2026Q1) 전부에서 성립하고 예외가 0건**입니다
(`tools/verify_model_issues.py` 로 재현 가능). 우연이 아니라 컬럼 정의가 그렇다는 뜻입니다.

그런데 현재 코드는 `점포_수` 를 전체로 가정합니다.

| 위치 | 현재 | 문제 |
|---|---|---|
| `src/features/build.py:127` | `TARGET = next_당월_매출_금액 ÷ next_점포_수` | 분모가 작아 **타깃이 과대** |
| `src/features/build.py:99` | `프랜차이즈_비율 = 프랜차이즈_점포_수 ÷ 점포_수` | 1.0 초과 (2025Q2 에서 1,554건, **최대 2,100%**) |
| `src/features/build.py:72` | `점포당_매출_t = 당월_매출_금액 ÷ 점포_수` | 같은 원인으로 과대 |
| `src/features/schema.py:8` | 주석의 타깃 정의 | 함께 갱신 필요 |

### 얼마나 벌어지나 (2025Q2 실측)

업종별 평균 부풀림 배수 — 프랜차이즈 비중이 큰 업종일수록 큽니다.

| 업종 | 배수 | | 업종 | 배수 |
|---|---|---|---|---|
| 편의점 | **3.10배** | | 커피-음료 | 1.34배 |
| 치킨전문점 | 2.23배 | | 제과점 | 1.29배 |
| 패스트푸드점 | 1.90배 | | 분식전문점 | 1.29배 |
| 슈퍼마켓 | 1.37배 | | 안경 | 1.29배 |

개별 상권에서는 훨씬 큽니다. 편의점 기준 상위 예시:

```
동대문역사문화공원역   전체 22개 = 일반  1 + 프랜차이즈 21  → 22배
양천향교역 7번        전체 15개 = 일반  1 + 프랜차이즈 14  → 15배
광화문역             전체 22개 = 일반  2 + 프랜차이즈 20  → 11배
```

한식음식점처럼 프랜차이즈가 적은 업종은 거의 영향이 없습니다. **업종에 따라 틀리는 정도가
다른 것**이 이 문제가 눈에 잘 띄지 않았던 이유로 보입니다.

### 요청

위 3곳의 분모를 `유사_업종_점포_수` 로 바꾸고 재학습해 주시면 됩니다.

- **`models/sales_model.pkl` 백업을 먼저** 부탁드립니다 (실데이터 189,411행 학습본입니다)
- 재학습 후 `build_serving_table.py` → `export_web_static.py` 재생성
- 성능 개선을 보장하는 변경은 아닙니다. **지표 정의를 바로잡는 것** 자체가 목적입니다
  (타깃이 바뀌므로 이전 MAE 와 직접 비교되지 않습니다)

### 저희가 함께 할 일

현재 웹에서 **점포 수·프랜차이즈 비율을 역산 보정**하고 있습니다
(`web-demo/lib/normalize.ts` 의 `correctStoreCounts()`, 보정 사실을 UI 3곳에 표시).
이 수정이 반영되면 **이중 보정이 되므로 저희가 그 코드를 제거**하겠습니다. 배포 순서를
맞춰야 하니 재학습·재생성 시점을 알려주세요.

## 4. (선택) 라이브 API 3개 보강

`MODEL_SERVER_URL` 을 켜면 아래가 동작하지 않습니다. **데이터 문제가 아니라 엔드포인트 부재**라
저희 쪽에서는 해결할 수 없습니다. 현재는 정적 산출물을 기본 경로로 두어 우회했습니다.

| 기능 | 원인 | 필요 작업 |
|---|---|---|
| 히트맵 생존율 | `/heatmap/{code}` 응답에 `closureRate` 없음 | `HeatmapItem` 에 필드 1개 추가 (~2줄) |
| 지역 우선 플로우 | 상권→업종 랭킹 엔드포인트 없음 (`/recommendations` 는 반대 방향) | 신규 엔드포인트 |
| 추이·요일/시간대 차트 | 서빙 테이블이 최신 분기 스냅샷이라 시계열 없음 | 별도 export 또는 엔드포인트 |

우선순위는 낮습니다 — 시연 기본값이 정적 경로이고, 정적이 생존율·차트 모두 더 낫습니다.

## 5. (선택) `meta.sources` 가 쓰지 않은 출처를 나열합니다

외부 데이터 없이 파이프라인을 돌려도 서버가 R-ONE·경찰청·CCTV 를 계속 출처로 나열합니다.
값은 `null` 로 정직하지만 **출처 목록은 사실과 다릅니다.**

원인: `api/dependencies.py` 가 `exports/meta/external_columns.json` 을 기동 시 그대로 읽고,
`build_features.py` 는 외부 컬럼이 없을 때 이 파일을 갱신하지 않아 과거 값이 남습니다.

해결: 서버에서 실제 값 유무로 필터링하거나, 외부 컬럼이 없을 때 이 파일을 비우도록 수정.
(§1 이 완료되면 자연히 사실과 일치하게 되므로 그 이후엔 불필요할 수 있습니다.)

## 확인해 주시면 좋은 것 하나

`검거 건수가 발생 건수를 초과하는 자치구가 있습니다` (예: 종로구 3,248 / 2,765 = 117%).
다른 기간 사건 검거 또는 검거 인원 집계로 보입니다. 저희는 원본 그대로 자치구 간 백분위에만
쓰고 화면에 '검거율' 로 표시하지 않았습니다. `sf_arrest_rate` 를 그대로 쓰는 것이 맞는지,
아니면 상한을 두는 것이 맞는지 의견 주시면 반영하겠습니다.
