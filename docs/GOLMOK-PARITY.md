| ~~행정동 4단 비교~~ → **✅ 8/6 구현** (⑤ 밀도) | `행정동_코드` + export 동 중앙값 | ✅ | 동 안에 상권 1개뿐이면(자기 자신) export 가 null → UI 생략. 임대는 값이 gu_mean 이라 동 층 무의미 — 서울 대비만 유지 |

## 3. ⚠️ 부분 — 근사·대체

| 서비스 기능 | 필요한 데이터 | 한계와 대체 |
|---|---|---|
| 행정동 폴리곤 + 수치 라벨 지도 | 행정동 경계 GeoJSON | 모델에 없음 (도입하면 데이터 주체 정책 위반) → 상권 점 마커·라벨로 대체. '동네 TOP10'은 리스트+드릴다운으로 해소 |
| **서비스 범위(서울) 표시** → **✅ 8/7 근사 구현** | 시 경계 폴리곤 (없음) | 상권 1,570개 좌표의 **convex hull** 로 커버리지 외곽을 파생 — 바깥 딤 마스킹 + 점선 + "상권 분포 외곽(근사)" 배지 + 줌아웃 제한(수도권까지). 행정 경계가 아니라 "상권이 있는 범위"라 서비스 커버리지로는 더 정직 |
| ~~상권영역 표시~~ → **✅ 8/7 원 근사 구현** | 상권 폴리곤 경계 | `영역_면적`으로 등면적 원(√(A/π)) + "44.4ha 근사" 라벨 + 클릭 지점→상권 중심 연결선. 실제 모양은 여전히 불가 (폴리곤 원천 없음) |

## 4. ❌ 불가 — 데이터 자체가 없음

golmok 이 내부적으로만 보유한 데이터라 공공 API 로도 받을 수 없다.
**"제공하지 않는 항목" 패턴**(리포트 ⑦ 방식)으로 이유와 함께 화면에 밝힌다.

| 서비스 기능 | 필요한 데이터 | 참고 |
|---|---|---|
| 보행권역/보행시간 분석영역 | 보행 네트워크 | 반경/다각형(🔧)으로 갈음 |
| 점포이력 지도 레이어 | 개별 점포 개폐업 이력 | 우리는 상권×업종 **집계**만 보유 |
| 유동인구 도로별/건물별 레이어 | 도로·건물 단위 유동인구 | 상권 단위만 보유 |
| 소득 7분위 | 소득 데이터 | `income.csv` 는 지출만 (기존 확정 한계) |
| 평균영업기간 | 점포 영업기간 | `store.csv` 에 없음 (개폐업 수/율만) |
| 가구의 아파트/일반 **분해** | `APT_HSHLD_CO` 실측값 | 컬럼은 있으나 전 구간 0 (8/6 실측) — 총가구만 제공, 아파트 세대는 아파트-상권 데이터셋으로 교차 표기 |
| 연차별 생존율 (1~5년차) | 연차별 생존 데이터 | 3년 환산(축소추정)이 우리 설계 결정 — 유지 |

## 5. 📐 비교 세션(8/7)에서 실증된 데이터 사실 — 되돌리면 안 됨

사용자가 golmok 과 나란히 놓고 보다가 잡아낸 것들. **화면 버그가 아니라 데이터
해석의 확정**이라 여기 기록한다 (다음 사람이 같은 의심을 반복하지 않도록).

| 실증 | 내용 | 반영 |
|---|---|---|
| **`당월_매출_금액` = 분기(3개월) 합계** | 점포당 값 ÷3 이 golmok '점포당 월평균'과 일치 (이문1동 한식: 우리 ÷3 = 747만~1,859만 vs golmok 1,454만 · 서울 한식 중앙값 ÷3 = 1,687만). 오래 "미확정"이던 항목 확정 | 전 화면 라벨 "월매출"→"분기" + 월평균(÷3) 병기. **"월"로 되돌리면 3배 부풀린 거짓** |
| **소표본 상권의 극단 매출은 실측** | 삼성중앙역 5번 한식 11.4억/8점포(중앙값 23배) · 영등포역지하도상점가 슈퍼마켓 27.6억/6점포(45배) — 모델이 아니라 원천이 그렇다 (대형 사업장이 소표본 평균을 폭등). golmok 은 행정동 단위라 희석돼 안 보일 뿐 | export 가 업종 중앙값 동봉 + `extremeNote`(중앙값 10배↑ & 소표본) 주입 → ③ 경고 박스. 값은 숨기지 않는다 |
| 상권 단위 vs 행정동 단위 | golmok 리포트는 행정동/선택영역, 우리는 상권 — 규모 수치가 다른 건 구조적 | 비교 시 전제로 안내 |
| **유동인구 밀도는 분기 연인원 ÷ 면적** | 서울 중앙값 **824만 명/km²** (상주 2.5만 · 직장 0.76만과 자릿수가 3배 다르다). 분자가 3개월 누적이라 그렇다 — ⑤ 타일이 이미 "유동 (분기)" 로 밝히고 있었다 | 랭킹 라벨도 "유동인구 밀도 (분기)" + scope 에 "유동인구는 분기 연인원". **÷91 일평균 환산은 하지 않는다** (원천에 없는 수를 만들지 않음 — '월매출' 정정과 같은 원칙) |
| 밀도의 분모 과소는 **상권에만** 있다 | 상권 면적 최소 1,854m² = 중앙값 75,550m² 의 **1/40** → 하위 5% 가 밀도 상위를 점령. 반면 행정동은 397개 중 면적 하한 미달 2개뿐이고 상위권(여의동·삼성1동·도곡2동)은 실제 오피스 밀집이다 | 상권 랭킹만 하위 5%(78개) 제외 + 제외 사실·기준을 화면에 표기. 동네는 제외 없음 — **밝히지 않고 행을 빼지 않는다**(제외 조건과 고지 조건을 한 변수로 묶음) |

같은 세션의 UX 반영: 대메뉴 분리(분석/상권 TOP10/비교함) · 패널 560px ·
섹션 분리감·탭 하이라이트(root 버그 수정) · 비교표 기본 접힘 · 상권 영역 원 근사 ·
차트 툴팁 가독성(itemStyle).

## 우리가 golmok 보다 나은 것 (실측 확인 — 빼면 손해)

- 랭킹 행 클릭 → 분석 진입 (golmok 은 랭킹에 클릭 핸들러가 없다)
- 증가율 랭킹의 소표본 노이즈 처리 (`lowBase` — golmok 은 "5만원 +326%" 가 1위)
- 동네 → 상권 드릴다운 (golmok 에 없는 경로)
- 종합점수·등급 / AI 예측 / 치안 / 독립점포 분석 / AI 인스펙터 (golmok 에 없음)
- 표본 부족의 정직한 처리 (축소추정 + low_sample 경고 — golmok 은 그대로 노출)
